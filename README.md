# Resume × JD Matcher · 简历与岗位匹配打分

把简历和 JD 放进去，输出**匹配分、技能缺口和改简历的方向**。支持 `.docx` / `.pdf` / `.txt`，也可直接粘贴文本。

> 做得比"让大模型打个分"多一点：先结构化抽取，再用**可复现的规则**算硬技能覆盖度，最后让模型补上规则算不出的判断，两部分加权并分别展示。

## 为什么不用一句 prompt 直接问模型「打几分」

| 问题 | 结构化 + 规则方案的回答 |
|---|---|
| 同一个简历跑两次分数不一样 | 硬技能覆盖是确定性的，同一输入结果恒定 |
| 分数是从哪来的 | 能看到匹配了哪些技能、缺了哪些 |
| 模型抽错了怎么办 | 界面直接展示抽取结果，错了一眼可见 |
| 换一份 JD 要重新调 prompt 吗 | 不用，JD 和简历都走同一套 schema |

## 流程

```
简历 .docx/.pdf ──► 抽取 JSON（学历/技能/项目）
                                    │
                                    ├─► 规则：必备技能覆盖度（确定性）
                                    │
JD 文本 ─────────► 抽取 JSON（必备/加分/年限）
                                    │
                                    └─► 模型：综合评分 + 差距 + 建议
                                                  │
                                    最终分 = 0.6 × 覆盖度 + 0.4 × 模型分
```

## 关键设计决策

### 1. 技能匹配要做同义词归一

`JS` / `JavaScript`、`k8s` / `Kubernetes` 不归一的话，覆盖率会被无谓拉低。
`src/score.py` 里维护了一张同义词表，并对中文技能名做映射（「大模型」→ LLM）。

### 2. 包含匹配设了最短长度

`go` 这种两个字符的技能名一旦用「包含」匹配，会把 `django`、`mongo` 全判成命中。
所以要求双方长度都不小于 3 才允许包含关系。

### 3. 结构化优先，规则兜底

评分不是纯模型输出。硬技能覆盖度用规则算，可复现、可单测；
模型只负责项目相关度、年限匹配、表述质量这类规则算不出的部分。
两者权重可配（`W_COVERAGE` / `W_LLM`）。

### 4. 抽取失败要能看见

界面里有「查看结构化抽取结果」面板，把两个 JSON 都摊开。
模型抽错字段时，用户能立刻发现，而不是对着一个莫名其妙的分数猜。

## 实测

| 场景 | 最终分 | 硬技能覆盖 | 说明 |
|---|---|---|---|
| 匹配度高的简历 vs AI 应用实习 JD | **83.2** | 80% | 缺「大模型基本原理」表述 |
| 非相关简历 vs 同一 JD | **7.2** | 0% | 5 项必备技能全缺 |

运行 `python eval/run_eval.py` 可复现，包含两项检查：**抽取字段完整性**与**排序正确性**（强简历分数必须高于弱简历——排序反了，分数再好看也没意义）。

## 快速开始

```bash
pip install -r requirements.txt
copy .env.example .env          # 填入 DEEPSEEK_API_KEY

python -m src.cli extract samples/resume_sample_strong.txt
python -m src.cli match samples/resume_sample_strong.txt samples/jd_ai_intern.txt
python -m src.cli match 简历.docx --jd-text "粘贴 JD 内容"
python app/ui.py                # 打开网页版（:7861）
```

## 目录结构

```
src/
  parse.py     # DOCX/PDF/TXT → 纯文本（含表格）
  extract.py   # 简历 / JD → 结构化 JSON
  score.py     # 同义词归一、覆盖度、模型评分、加权
  llm.py       # OpenAI 兼容接口封装，带重试
  cli.py       # extract / match
app/ui.py      # Gradio 界面
eval/          # 用例与评测脚本
samples/       # 示例简历与 JD
```

## 已知限制

- 技能抽取依赖模型，专业术语可能有遗漏或过度归纳
- 没有做岗位推荐（只做单份 JD 匹配）
- 学历、年限只是简单比对，不考虑专业相关性
- 示例简历为虚构数据
